Detailed Algorithm Comparison Analysis
=======================================

1. SCC Algorithm (Tarjan)
   Time Complexity: O(V + E)

   Purpose:
   - Identifies strongly connected components (groups of vertices reachable from each other)
   - Compresses cyclic dependencies into single nodes
   - Required preprocessing step for topological sort on cyclic graphs

   Performance Characteristics:
   - Cyclic graph example (small_2_cyclic): 7 vertices compressed to 5 SCCs (28,6% reduction)
   - Acyclic graph example (small_1_acyclic): 8 vertices = 8 SCCs (no compression)
   - DFS visits always equal vertex count (must visit all vertices)
   - Execution time: 0.005-0.020 ms for tested graphs

   When to Use:
   - Essential for graphs with potential cycles
   - Required before topological sort if cycles may exist
   - Use when you need to identify dependency groups
   - Skip for known acyclic graphs (adds overhead without benefit)

   Best Performance:
   - Fastest: 0,005 ms, Slowest: 0,020 ms
   - Performance depends on graph structure, not just size


2. Topological Sort (Kahn's Algorithm)
   Time Complexity: O(V + E)

   Purpose:
   - Determines valid execution order respecting dependencies
   - Works on DAG (directed acyclic graph)
   - Required for scheduling tasks with dependencies
   - Enables shortest path algorithms on DAGs

   Performance Characteristics:
   - Operates on condensation graph after SCC compression
   - Example: small_2_cyclic reduced from 7 to 4 edges (42,9% reduction)
   - Queue-based BFS approach - very efficient
   - Execution time: 0.005-0.027 ms for tested graphs

   When to Use:
   - Always needed for task scheduling problems
   - Required before DAG shortest path computation
   - Use when you need valid execution sequence
   - Best for dependency resolution in build systems, project management

   Performance Comparison:
   - Average time: 0,015 ms
   - Slightly slower than SCC on average (operates on compressed graph)


3. DAG Shortest Path Algorithm
   Time Complexity: O(V + E)

   Purpose:
   - Computes shortest paths from source vertex to all reachable vertices
   - Finds longest path (critical path) for project duration estimation
   - Uses dynamic programming over topological order
   - Applicable only to DAGs (no negative cycles possible)

   Performance Characteristics:
   - Relaxations = number of edges processed
   - Dense graph example (large_3_dense): 84 edges require 84 relaxations
   - Execution time correlates directly with edge count
   - Execution time: 0.001-0.013 ms for tested graphs
   - Fastest algorithm among the three on most graphs

   When to Use:
   - Essential for project scheduling (critical path method)
   - Use for finding minimum/maximum execution time
   - Required for resource allocation optimization
   - Best for finding bottlenecks in task networks

   Performance Bottlenecks:
   - Dense graphs: large_3_dense with 84 edges takes 0,012 ms
   - Large graphs: large_3_dense with 84 edges takes 0,012 ms
   - Linear scaling: more edges = proportionally more time


Comparative Performance Analysis
=================================

Speed Ranking (average execution time):
   1. DAG Shortest Path: 0,005 ms (fastest)
   2. SCC (Tarjan): 0,012 ms
   3. Topological Sort: 0,015 ms

Scalability Analysis:
   Graph size increased 3,8x (8 to 30 vertices)
   - SCC time increased 2,3x (scales sub-linearly)
   - Topo time increased 1,3x (scales sub-linearly)
   - DAG-SP time increased 2,4x (scales sub-linearly)

Effectiveness of SCC Compression:
   Overall: 160 vertices -> 150 SCCs (6,3% reduction)
   Overall: 257 edges -> 242 SCC edges (5,8% reduction)

Use Case Recommendations
=======================

For Pure DAGs (no cycles):
   - Skip SCC, use Topological Sort directly
   - Then apply DAG Shortest Path
   - Fastest workflow: Topo Sort -> DAG-SP

For Graphs with Cycles:
   - Required workflow: SCC -> Topo Sort -> DAG-SP
   - SCC compression is essential for subsequent steps
   - Compression efficiency depends on cycle size and count

For Dense Graphs (many edges):
   - DAG-SP will require more relaxations
   - Topo Sort handles density well (queue-based)
   - SCC performance less affected by density

For Large Graphs (50+ vertices):
   - All algorithms maintain linear scaling
   - Execution times remain in millisecond range
   - No performance degradation observed

Conclusion
==========

All three algorithms are efficient and scale linearly with graph size.
The choice depends on problem requirements:

- Need to handle cycles? Use SCC first.
- Need execution order? Use Topological Sort.
- Need path optimization? Use DAG Shortest Path.
- For task scheduling: Use all three in sequence (SCC -> Topo -> DAG-SP).

Performance is production-ready for graphs up to 50+ vertices with
execution times under 0.03 ms per algorithm on tested hardware.
